# LP LoRA Trainer 项目架构

- 版本：0.4
- 日期：2026-10-07
- 状态：基础业务、桌面启动、本机 API 与 Kohya CLI 训练适配已实现；真实 GPU 训练待验收。
- 依据：`项目计划.md` 0.6；保留已确认前端设计，不更改布局和主题样式。

## 1. 架构原则

1. 独立桌面应用，不依赖 ComfyUI；ComfyUI 只是可选产物发布目录。
2. pywebview + Vue 3 / TypeScript / Vite + FastAPI，不做额外前端选型或性能原型。
3. 直接把用户源码复制到 `engine/`；`adapters/<engine>/` 一个文件夹对应一种引擎接口适配。
4. 代码 revision、解释器环境与安装实例分别记录，任务提交时固定绑定。
5. 训练交给引擎原生 CLI，窗口和管理服务不加载训练模型，不介入训练 step。
6. 桌面、API、supervisor 和训练子进程解耦，关闭窗口不会结束训练。
7. 只声明已实现能力；AI Toolkit 与 Musubi Tuner 当前不支持提交训练，不伪造状态、进度或指标。
8. 不替用户下载、更新或删除引擎主仓库，官方安装器可按其流程初始化所需子模块；仅在用户显式确认后，通过适配器调用引擎环境安装流程。

## 3. 进程拓扑与生命周期

```text
Desktop / pywebview + WebView2
             │ 同源 HTTP / SSE
             ▼
       FastAPI / Uvicorn ─── SQLite + 任务目录
                                      ▲
                                      │ 条件更新、状态/日志记录
                                      ▼
                        独立 supervisor.worker
                                      │ argv + cwd + env，shell=False
                                      ▼
                         引擎自己的 Python / CLI
```

### 已实现行为

- `desktop.launcher` 检查前端是否构建，使用单实例锁，连接本机 API 或后台启动 API。
- 重连验证后端版本和 `data_root` 身份，防止误连其他数据目录的后端。
- API 生命周期启动独立 supervisor；后者有独立进程锁，避免同一数据目录重复调度。
- 关闭 WebView 不终止 API、supervisor 或训练子进程。重新打开窗口可继续查看任务。
- API 通过 SQLite 和任务文件下发控制请求、读取状态；当前没有另建常驻消息代理。
- supervisor 单 GPU 顺序处理队列；任务开始前复核源码、环境 manifest、adapter 版本和配置 hash。
- 监管重启时，原准备/运行/停止中任务进入 `connection_lost`，不重放、不按历史 PID 擅自杀进程。
- 存在 `connection_lost` 时阻塞后续队列；用户必须核实进程和子进程退出，再显式确认。

后台服务默认不弹出无关控制台。管理层不创建训练模型；显式环境诊断在选定解释器的临时子进程中检查依赖与 CUDA 可用性。WebView 渲染仍有自身资源开销，不声称零显存或零开销。

## 4. 模块边界

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| frontend | 表单、状态展示、历史及增量事件、用户确认 | 执行 Python、读取任意文件、生成未经后端验证的训练命令 |
| desktop | 窗口、本机服务连接、路径对话框、系统定位 | 训练调度、引擎依赖安装 |
| API / services | 输入校验、实例及数据集管理、配置生成、状态查询 | 模型训练、CUDA 常驻、自动修改用户引擎 |
| supervisor | 独立队列、进程生命周期、原始日志、指标与产物登记 | 前端布局、自动恢复未知进程 |
| adapters | 静态识别、能力、原生配置、CLI、日志、恢复能力声明 | 通用数据库、GUI、下载与环境管理 |
| storage | SQLite 与本地记录 | 把完整模型或源图片放入数据库 |

适配器显式注册，不动态执行 `engine/` 内的插件代码。扫描是静态识别；绑定诊断和训练启动才执行用户选择的解释器。用户复制的引擎及其环境必须可信。

## 5. 引擎实例与版本管理

### 5.1 复制即发现

```text
复制到 engine/<任意实例名>/
→ 枚举一级安装目录
→ 注册适配器静态 detect
→ 登记 source_path、候选类型和源码 revision
→ 类型冲突时人工确认
→ 显式确认安装（无需先绑定 Python），或绑定已有引擎内独立 Python
→ 项目内 uv 引导 + 各引擎官方安装器
→ 自动发现并保存解释器、执行诊断、记录 manifest
→ 状态就绪后允许支持的训练
```

支持 Kohya 根目录和含 `sd-scripts/` 的包装目录。同一种引擎的多个版本实例都使用一个 `adapters/kohya/`，不按版本复制整套接口代码。实例身份按源码绝对路径登记，不依赖目录名称。

### 5.2 固定绑定

源码 revision 记录 Git 线索（如可用）及相关源码文件的内容指纹；没有 `.git` 也能登记。扫描时过滤环境、模型、输出和缓存目录，Git remote 的账号密码不直接入库。

诊断记录 Python、PyTorch、CUDA 等环境信息，生成 manifest 和环境标识；复制源码或虚拟环境不意味着已就绪。任务绑定包括：

- 安装实例及源码路径/revision 快照；
- Python 解释器和环境 manifest 标识；
- adapter 版本及 schema 版本；
- 原生配置及任务文件 hash。

默认实例切换只影响新配置；排队任务启动前再次复核绑定，源码或配置变化导致明确失败而不是静默使用新版本。环境 manifest 是诊断摘要，不是整个虚拟环境的完整冻结镜像。

### 5.3 当前支持范围

- Kohya：SD1、SD2、SDXL 单 GPU LoRA，原生 CLI 和 TOML 配置；解析可识别的 tqdm step / loss，其他日志保留原文。
- AI Toolkit：静态识别、实例/版本记录、诊断和适配器安装流程；训练能力明确拒绝，待实现原生 CLI 适配。
- Musubi Tuner：静态识别、实例/版本记录、诊断和适配器安装流程；训练能力明确拒绝，待实现训练参数映射和启动适配。
- 用户显式启动环境安装，无需预先绑定 Python。Kohya 通过 uv 创建 Python 3.11 `venv`、准备官方要求的 setuptools，再调用 `setup/setup_windows.py --headless`；AI Toolkit 调用 `manager/__main__.py install`；Musubi 调用 `uv sync`，仅接受源码声明的 CUDA extra。
- 应用运行时只执行标准库引导，uv / managed Python / 缓存位于 `runtime/uv/`，训练依赖位于各引擎 `venv` / `.venv`，不写入应用 `python_runtime`。
- 安装会话先保存发现的解释器，再自动诊断；诊断失败不报告成功。终端实时日志、取消进程树、失败重试和重启中断恢复见 `运行与安装.md`；一次仅允许一个安装，活动训练阻止安装。
- 自动候选更新、依赖锁定、自动回滚和卸载清理尚未实现。
- 当前不保证任意上游版本兼容，没有完成真实 GPU 与目标 ComfyUI 的加载验收。

`profiles/` 与 `templates/` 保留扩展位置；现阶段 Kohya 配置映射在 `adapter.py` 中实现，不把空目录当作已完成兼容矩阵。

## 6. 数据集与配置

数据集使用外部绝对路径引用。扫描建立图片索引与尺寸、损坏、缺失 caption 等问题；图片分页并使用缓存缩略图，不默认复制或上传全部图片。

Caption 写入前检查图片/文本路径仍在登记目录内，旧文本先备份，再原子替换。当前不提供自动打标、裁剪、增强或批量 caption 工作流。

训练表单的固定基础字段和能力驱动参数由后端一起校验，校验成功后返回原生 TOML 预览及 argv。后端拒绝不存在的模型、未扫描的数据集、不可用的引擎环境、不支持的参数或架构。

当前 Kohya dataset TOML 使用登记目录一级图片；存在子目录图片时拒绝提交，避免遗漏。输出目录不能位于引擎源码、数据集、基础模型或应用数据内部，任务输出使用用户输出目录下独立的 task-id 子目录。

## 7. 任务执行与停止语义

```text
配置校验 → 固定绑定/写入任务目录 → queued
→ preparing / 复核绑定 → running
→ succeeded / failed
             └─ 停止请求 → stopping → stopped

无法确认进程退出、监管曾中断 → connection_lost → 人工核实并确认 → stopped
```

- 使用参数数组、工作目录和环境覆盖启动进程，不使用 shell 命令字符串。
- SQLite 条件更新协调排队取消与 supervisor 认领，已取消排队任务不会再次执行。
- 普通中断先发送信号；超过等待时间尝试强制结束。Windows 使用进程组与 `taskkill /T /F` 控制进程树。
- 强制结束失败、仍有日志管道或未知子进程时不声称任务已停止，进入 `connection_lost` 并阻塞队列。
- 迟后退出的子进程会被回收，但不会以此替代用户对未知进程树的人工确认。
- 停止不保证保存 checkpoint；当前恢复能力明确为不支持权重续训/完整状态恢复。
- 引擎非零退出码不会被标为成功；未知指标显示未知，不生成伪造进度。

## 8. API、安全与前端同步

API 前缀 `/api/v1`，入口仅监听本机地址。请求检查 Host、Origin、跨站来源和会话；同源 `POST /session` 建立 HttpOnly / SameSite=Strict Cookie，HTTP 和 SSE 共用会话，401 自动重新建立。会话密钥不出现在 URL 中。

HTTP 负责引擎、数据集、校验/提交、任务控制、产物发布和设置。SSE 负责 `task.updated`、`task.log`、`task.metrics`、`engine.updated` 与 `system.status`。

事件断线后重新建立会话及 SSE，先刷新系统/任务/引擎快照，再应用批量事件，同时刷新当前任务历史日志和指标，补上离线更新。前端可见时约 2 Hz 合并事件，隐藏时降频，日志和图表缓存有上限；后端按文件偏移读取增量，而不是反复发送完整日志。

pywebview 桥接仅提供路径选择、资源管理器定位和受限窗口控制（最小化、最大化/还原、关闭、固定方向边缘缩放及状态读取），不提供任意命令执行、任意窗口句柄或系统消息接口。生产界面不依赖在线 CDN。开发示例模式仅在开发构建启用，并明确禁止写操作。

保持原页面设计、CSS 与组件样式，只补 API/状态逻辑和必要操作文案；Logo 用 LP 替换原菱形图案，不调整导航布局。

## 9. 产物登记与发布

训练结束后登记模型和采样图。safetensors 校验 header、tensor shape / dtype / offsets 及 payload 长度，不加载权重；未知格式不会当作可用模型。采样图进行可解码验证。

发布必须由用户显式选择模型，检查完整状态、源文件仍可用、文件名和目标目录。源文件及临时复制文件均重新校验，避免登记后损坏的模型被发布。先写目标目录临时文件，再使用无覆盖的原子 hard-link 创建最终文件，清理临时文件；目标已存在或文件系统不支持该发布方式会明确报错，不退回有覆盖风险的复制。

不默认发布全部 checkpoint，不调用 ComfyUI API，也不修改 ComfyUI 环境。结构校验不是模型质量或目标架构兼容性验证。

## 10. 运行数据布局与设置

```text
engine/                         # 用户源码；根路径可在设置中调整
runtime/
├─ desktop.lock
└─ backend.log

data/                           # 默认 data_root
├─ state.sqlite                 # 索引、设置及任务状态
├─ backend.lock
├─ supervisor.lock
├─ supervisor.json              # 心跳，不是训练恢复点
├─ manifests/<manifest-id>.json  # 环境诊断摘要
├─ cache/                       # 缩略图缓存
└─ jobs/<task-id>/
   ├─ job.json
   ├─ binding.json
   ├─ dataset.toml
   ├─ config.native.toml
   ├─ command.json
   ├─ stdout.log
   ├─ metrics.jsonl
   └─ artifacts.json
```

任务绑定和索引也保存于 SQLite。模型及采样图仍位于用户输出目录的 task-id 子目录，图片仍位于用户数据集目录；不塞进数据库。

构造 `AppPaths` 不创建目录，服务启动后按需初始化运行数据。`data_root` 不支持运行中切换；迁移需停下后台服务，复制数据并通过 `--data-root` 重启。GPU 监控默认关闭，启用后低频调用 `nvidia-smi`，缺失时返回未知，不伪造 GPU 信息。

## 11. 验证状态与后续工作

当前 25 项后端自动化测试覆盖复制识别、多实例绑定、路径保护、数据集/caption、原生配置、真实模拟子进程、异常退出、强制停止、失联处理、模型发布和本机 API 安全；前端 TypeScript 检查与生产构建通过。Windows 进程树测试需要允许 `taskkill`。

这些测试不代表已经使用真实 GPU 跑完上游引擎，也不构成性能对照或 ComfyUI 加载验收。当前不追加独立前端性能验证。

后续优先：可信引擎与模型上的 Kohya / SDXL 最小 GPU 训练、兼容版本档案、AI Toolkit 原生训练适配。引擎版本自动更新/回滚、恢复训练和多 GPU 调度另行分阶段实现，继续保持既有前端视觉设计。

## 12. 独立且可迁移的应用 Python

日常运行使用 `python_runtime/`：内含完整 Windows x64 CPython EXE/DLL、标准库、应用依赖及许可证，而不是普通 `.venv`。`.venv` 仅用于开发与制作交付包；用户拿到完整目录后无需系统 Python、pip 或 Node.js。

`pythonXY._pth` 仅列出相对目录，不导入 `site`，隔离 Python 环境变量、注册表路径、user site-packages、editable hooks 和当前工作目录。`LP-Lora-Trainer.exe` 用自身目录定位随包 `python_runtime\pythonw.exe`，以无控制台方式启动 `desktop.launcher`；后端/supervisor 用 `sys.executable` 启动，形成同一运行时的进程链。`start.cmd` 仅作为兼容命令行入口。Python.NET 所需 Windows .NET Framework 和 WebView2 仍是操作系统组件，不是额外系统 Python。

`scripts/build_python_runtime.py` 离线复制构建机完整 CPython 与 pyproject 定义的应用/desktop 依赖闭包，校验依赖版本、平台 marker、递归 extras 和文件路径。自检成功后才将暂存目录发布为运行时；重建保留旧版本，不自动删除用户目录。`runtime-manifest.json` 记录实际 Python 和依赖版本；依赖升级在构建机进行，再发布完整运行时，不在用户机器启动时 pip install。

交付包需包括 `LP-Lora-Trainer.exe`、`python_runtime/`、应用源码及 `frontend/dist/`；`LP-Lora-Trainer.exe` 可由 `scripts/build_launcher.ps1` 重建。测试覆盖污染 Python 环境变量、仅保留 OS 工具的 PATH、原生库导入、子进程传播及含空格/中文的新路径。检查不打开 GUI，不做性能基准，不等同于无 Python 的新电脑/真实 GPU 端到端验收。

引擎环境仍独立：复制源码不等于具备依赖；安装通过项目内 uv 获取基础 Python，不需要系统 Python。普通引擎 `venv` / `.venv` 仍可能引用绝对路径，不保证跨电脑/盘符直接运行，迁移后需重新安装或绑定并诊断。当前不制作可任意迁移的整套训练环境包，不篡改历史任务绑定。

## 13. 同主题桌面标题栏

使用 pywebview 无边框窗口与 Vue `WindowTitleBar`，以既有深灰配色、系统字体、圆角按钮及 LP 图形替代系统标题栏；业务页面、导航与主题不变。标题栏高度 40px，只有桌面原生桥接就绪时显示，普通浏览器布局不额外占用标题栏空间。

支持最小化、最大化/还原、关闭、标题区域拖动与双击，以及 Windows 四边/四角缩放。拖动区域不包含按钮；最大化限定到当前显示器工作区。最大化状态采用原生事件通知并读取实际窗口状态，不轮询；缩放只提交一次受限原生请求，由 Windows 执行交互循环。

关闭窗口只调用窗口销毁，不停止本地 API、supervisor 或训练。没有增加运行依赖、在线字体、动画框架或常驻窗口状态定时器。真实窗口的多显示器/DPI、拖拽与缩放交互仍需在目标电脑人工验收。
