# 启动权限与导出修复

## 原因与目标

应用 EXE 和便携 Python 若继承 Windows 低完整性（Low Integrity）标签，会使启动的 Python 也以低完整性运行。此时即使用户在下载、文档目录拥有普通写权限，保存对话框或实际写入仍会拒绝访问；低完整性项目目录内部的写入却可能成功。

修复纳入发布构建和 EXE 启动，不要求用户手动执行命令，不要求主程序长期以管理员运行。不能承诺绕过目标目录真实的 ACL、只读文件或企业策略限制。

## 发布构建

- `scripts/build_launcher.ps1` 编译启动器与共享原生完整性检查代码，再规范化并检查启动文件标签。检查失败则构建失败。
- `scripts/build_python_runtime.py` 在暂存 Python 自检与发布前规范化标签，防止低完整性构建目录污染便携包。
- `scripts/check_runtime.py` 检查实际进程完整性，并在项目外的用户临时目录写入、读取和清理配置文件。只在项目目录写入不能验证此问题。
- `desktop/windows_integrity.cs` 读取进程 token 与文件完整性标签，不修改普通文件访问权限。
- `scripts/repair_startup_integrity.ps1` 只处理应用 EXE、便携运行时目录本身以及其中的 `python.exe`、`pythonw.exe`。没有递归权限重置，没有修改引擎、数据集或用户文件夹 ACL。
- 发布应通过常规 ZIP 打包，不将开发机 ACL / SACL 作为安装权限复制到目标电脑。构建脚本与 `desktop/windows_integrity.cs` 应随便携项目保留，供旧副本修复使用。

## 启动流程

1. EXE 在启动 Python、后端与 supervisor 前检查自身进程和三个启动 EXE 的完整性。
2. 正常发行包直接启动，没有额外终端，没有提权流程。
3. 普通进程发现旧 Python 文件被低完整性标记，先尝试无提权修复。
4. 若启动器自身已经处于低完整性，或普通修复失败，则通过系统 PowerShell 请求一次 Windows UAC 授权，修正限定的应用文件标签。
5. 需要修复进程完整性时，由桌面 Shell 重启应用，保留原命令行参数；修复辅助进程退出，主程序不继承辅助进程的管理员权限。旧启动器不再启动第二套后端。
6. 用户取消 UAC 或修复失败时，明确说明应用未启动，不留下后台 Python。
7. 若文件标签正常但父进程本身受沙盒限制，应用不尝试解除沙盒，只说明应从正常桌面入口打开。

Windows 不允许低完整性进程自行提升完整性，旧副本的一次系统授权不能用程序静默绕过。需要管理员凭据的受管电脑，应由发行或部署方提供权限正常的包。

## 导出与兼容

- 导出仍使用当前桌面“另存为”接口；用户取消不是错误。
- Python 写入遇到权限错误时，报告目标路径，区分低完整性运行与普通目标目录拒绝，不显示成功。
- 浏览器导出及 `desktop/launcher.py` 的 `desktop_bridge_error()` 预检、`spawn_console()` 回退保持原有流程。
- `LP-Lora-Trainer.exe --check-startup-permissions` 提供无界面的发布诊断：0 表示预检通过，3 表示受限进程或低完整性文件。该诊断不自动修复，也不启动后端。

## 验证

自动化验证真实低完整性可执行文件会产生低完整性进程、发布检查拒绝异常标签、限定修复后恢复、修复前后 DACL 相同、外部目录拒绝、暂存构建目录兼容，中等完整性原生启动链路加载桌面桥接并导出配置，以及桌面 Shell 在正常权限下调用实际 `DesktopBridge.save_text_file()` 写入项目外目录。

自动化测试不点击 UAC 或操纵真实保存对话框；这两个系统交互需人工发布验收。
